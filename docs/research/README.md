## 06-mental — ментальное здоровье

**Отчёт готов** (27.10). Ждёт решения владельца.

| Файл | Что внутри |
|---|---|
| `BRIEF.md` | постановка задачи, 17 КБ |
| `REPORT.md` | отчёт, 29 КБ |
| `_sources.md` | 36 статей Europe PMC с DOI и абстрактами |

**Главное из отчёта:**
- эмоция и эпизод — разное; медиана эпизода 3 месяца (Spijker 2002)
- ломает не сила боли, а неизбегаемость (Baratta/Seligman 2023)
- ангедония — отдельная ось (ΔD), не «сильная грусть» (Kao 2026)
- выгорание — не болезнь, другая структура
- модель: `load` + `agency_erosion` поверх существующих переменных
- главный риск: она начнёт **изображать** болезнь; защита — менять
  способность, не самоописание

**Внедрение по шагам:** (1) только считать, (2) стадии и влияние,
(3) выгорание, (4) связь со сном.

## 07-sleep — сон

🔨 **НА РЕАЛИЗАЦИЮ** (отмечено владельцем 27.10).

Отчёт готов. Внедрение по шагам — в разделе 6 `REPORT.md`.

| Файл | Что внутри |
|---|---|
| `BRIEF.md` | постановка: сон как единый восстановительный процесс |
| `REPORT.md` | отчёт, 30 КБ |
| `_sources.md` | 33 статьи Europe PMC с DOI |

**Главное из отчёта:**
- REM — состояние с **дефицитом моноаминов** (Chen 2026); наш
  `shift_toward_baseline` во сне делает наоборот
- медленные волны укрепляют, дельта ослабляют (Golden 2026) —
  баланс и есть механизм «что забыть»
- плохой сон ломает эмпатию причинно: 5 пробуждений достаточно
  (Gordon-Hecker 2025)
- дефицит SWA → тревога наутро, медиация полная (Ben Simon 2026)
- руминация → плохой сон → порочный круг, который надо сохранить
- `agency_erosion` сном почти не лечится (10%) — контроль
  восстанавливается опытом, не отдыхом

**Шаг 1 (одна строка):** `_do_sleep()` должен звать `affect.on_wake()`.

### Что известно (проверено 27.10)

| Факт | Где |
|---|---|
| Сон по расписанию `add_daily("sleep", 4:00)` | `app.py:281` |
| **В фоновом режиме не регистрируется вообще** | `app.py:266-285`, ветка `else` |
| `/sleep` — команда владельца, не её | `app.py:1467` |
| По своей воле спать **не может** | нет скилла, нет действия в проактивности |
| `_do_sleep()` **не зовёт** `affect.on_wake()` | `app.py:1561-1568` |
| `on_wake()` вызывается **только из тестов** | `test_affect_service.py:251,257` |
| Усталость накапливается линейно | `fatigue_awake_rate = 0.0000347`/с = 1.0 за 8 ч |
| Восстановления нет — застревает на 1.0 | следствие двух пунктов выше |

### Почему это важно

При `fatigue = 1.0`:
```
fatigue_cut = 1.0 - 0.35 * 1.0 = 0.65
max_tokens  = 700 * scale * 0.65      ← обрезано на треть
базовая S снижена на -0.20, N на -0.15, D на -0.30
```

Она **структурно не может восстановиться**. Каждое сообщение
добавляет усталость, ничто её не снимает.

### Что надо сделать (когда дойдём)

1. `_do_sleep()` → вызов `affect.on_wake()` — одна строка, лечит
   застревание.
2. Сон в фоновом режиме — сейчас `add_daily("sleep")` только в
   `else`-ветке.
3. `fatigue_awake_rate` — 8 часов до полной усталости слишком быстро
   для существа, живущего в телефоне круглосуточно.
4. **Дать ей волю спать** — скилл `sleep`, порог усталости,
   решение в проактивности.
5. **Связать с менталкой** — сон должен восстанавливать не только
   `fatigue`, но и эмоциональный фон: снимать руминацию, снижать
   социальную боль, возвращать моноамины к базе.

## 08-identity — идентичность собеседника

**Отдано внешнему архитектору** (27.10). Ждём ответа.

| Файл | Что внутри |
|---|---|
| `BRIEF.md` | задание: различать «с кем говорю» и «о ком вспоминаю» |
| `IDENTITY_PACK.md` | 831 КБ — задание + код + все исследования |

**Требование владельца (дословно):**
> «не надо изолировать память по чатам. надо чтобы она понимала,
> с кем общается и про кого эти воспоминания. нормально если я
> люблю кофе и она вспоминает про другого, но она должна понимать,
> что болтает щас с другим человеком, а вспоминает про другого.»

**Что проверено в коде:**
- `speaker` в эпизодах пустой у **всех 142** записей
- **23% памяти** (33 эпизода) с `chat_id=0` — не знает, откуда
- причина: `_diary_save` склеивает историю всех чатов в одну кашу
  и пишет без `chat_id` и без автора
- три пути поиска (`retrieve`, `flash`, `recent`) не принимают `chat_id`
- `user_id` в `relation_weights` = None, привязанность по чату

**Что работает правильно и не трогать:** история диалога по чатам,
социальная боль, руминация.

**Главный вопрос задания:** как обеспечить различение
**структурно**, а не уговорами в промпте.

**Требование владельца (дословно):**
> «слип тдет она сама когда уже чувствует усталость но у нее должен
> быть конкретный такой режим. она может задержаться потому что
> написала кому то и ждет ответа, с кем то переписывается и всякое
> такое.»

**Что проверено в коде:**
- сон работает **только по расписанию 4:00**, сама не ложится
- `fatigue` растёт до 1.0 за 8 часов и никуда не сигналит
- **менталка не внедрена вообще**: `load`, `agency_erosion`,
  `depletion`, `MentalState` — ни одного вхождения
- `night_enabled = false`; ночной режим телеграма ≠ сон
- `NightQueue` уже есть: сообщения копятся, утром пачкой

**Главный вопрос задания:** как отличать «хочу спать, но жду ответа»
от «хочу спать и мне нечего ждать» — структурно, а не уговорами
в промпте.

**Связанные отчёты:** `06-mental/REPORT.md`, `07-sleep/REPORT.md` —
