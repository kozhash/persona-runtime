Архитектура автономного сна,
ментальной нагрузки и аффективной
регуляции в конвейере persona-runtime
Существующая реализация persona-runtime располагает развитым нейромодуляторным движком,
основанным на системе связанных обыкновенных дифференциальных уравнений (ОДУ) для
серотонина (S), норадреналина (N) и дофамина (D), интегрируемых методом Рунге — Кутты
четвёртого порядка (RK4), а также когнитивным автоматом социальной боли по темпоральной
модели Уильямса и трёхфазным консолидатором эпизодической памяти (NREM, REM, FORGET).
Несмотря на зрелость отдельных компонентов, между этими подсистемами сохраняется
критический архитектурный разрыв: гомеостатическая усталость (fatigue) линейно возрастает до
1.0 за восемь часов бодрствования, но не инициирует переход ко сну, сам сон реализован как
мгновенный процедурный вызов по расписанию в 04:00 без протяжённого во времени состояния,
а теоретически спроектированная модель ментального износа (load, agency_erosion, depletion)
физически отсутствует в кодовой базе. Вследствие этой изоляции персонаж (персонаж, 22 лет,
архиволшебница из Konosuba) не способен самостоятельно ощутить потребность в отдыхе,
задержаться в сети ради ответа собеседнику или пережить каскадное ухудшение состояния при
хронической депривации сна и неконтролируемом социальном стрессе.
Настоящее архитектурное решение устраняет указанный разрыв путём бесшовного слияния
автономного цикла сна, детерминированного трекера диалоговых обязательств и интегратора
ментального состояния в единый вычислительный конвейер. Проект разработан с жёстким
соблюдением эксплуатационных ограничений системы: использование одного общего эндпоинта
LLM API без массовых параллельных вызовов, полный отказ от обращения к языковой модели
для расчёта порогов и переходов состояний, временная компрессия цикла сна и стопроцентная
обратная совместимость с существующими 257 тестами.
1. Структурное разрешение главного вопроса:
детерминированный автомат ожидания против промпт-
инструкций
Попытка решить задачу «персонаж хочет спать, но задерживается, так как ждёт ответа от
собеседника» путём добавления текстовых уговоров в системный промпт обречена на провал по
двум фундаментальным причинам, вытекающим из устройства KuniApp. Во-первых, сборка
системного промпта в PersonaBuilder.build() происходит исключительно в момент генерации
ответа на входящее сообщение (_full_reply) или при срабатывании редкого проактивного тика
(proactive_send). В интервалах молчания собеседника языковая модель вообще не вызывается, а
значит, любая инструкция внутри промпта физически лишена возможности управлять таймингом
засыпания или принимать решение о прекращении ожидания. Во-вторых, LLM не обладает
восприятием реального физического времени между репликами и склонна либо игнорировать
числовую телеметрию — как показал инцидент от 26.10, когда при соматическом удовольствии P
= -0.65 и обнулённых потребностях модель сгенерировала оценку «веселье 72%, обижаться не
буду», — либо уходить в театральный отыгрыш сонливости вместо фактического прекращения
ответов.
Следовательно, разграничение между состояниями «хочу спать и мне нечего ждать» и «хочу
спать, но удерживаема незакрытым социальным контекстом» должно быть вынесено из промпта
на уровень детерминированного автомата управления диалогом (Dialogue Turn &
Commitment Tracker), функционирующего в событийном цикле KuniApp полностью без участия
LLM.
1.1. Таксономия социальных и когнитивных якорей бодрствования

В архитектуре систем управления многошаговыми диалогами состояние каждого
коммуникативного потока после отправки исходящей реплики строго разделяется на закрытое
(resolved/idle) и ожидающее обратной связи (awaiting reply). Применительно к persona-runtime эта
концепция формализуется через состояние обязательств чата ChatCommitment для каждого
chat_id, которое обновляется синхронно при отправке и получении сообщений в app.py. Анализ
поведенческих требований позволяет выделить четыре структурных удерживающих фактора
(якоря), препятствующих переходу в сон даже при высоком гомеостатическом давлении
усталости.
Первым и ключевым якорем выступает ожидание ответа на собственную инициативу
(awaiting_reply), возникающее тогда, когда агент совершил коммуникативный вклад, требующий
реакции партнёра, и дофаминовый цикл ошибки предсказания награды (\text{RPE}) остаётся
незакрытым. Детерминистическими триггерами этого состояния в коде служат проактивная
отправка сообщения первой через proactive_send() (источники proactivity.impulse,
proactivity.thoughts, autochat), наличие вопросительного знака (? или ？) в последнем
отправленном сообщении агента в личном чате (private) или в адресном ответе в группе, а также
отправка реплики на фоне высокой аффективной вовлечённости — когда интенсивность текущей
эмоции emotions.state.intensity >= 0.55, активен след руминации rumination(chat_id) или вес
привязанности к собеседнику удовлетворяет условию w_rel >= 1.5 (включая владельца, для
которого w_rel = 2.5).
Вторым якорем является активный живой разговор (active_dialogue), представляющий собой
фазу синхронного обмена репликами, когда с момента последнего сообщения собеседника, на
которое агент дал ответ, прошло менее \tau_{\text{active}} = 300\text{ с} (5 минут), а плотность
диалога составляет не менее двух пар реплик за последние 10 минут. Внезапное отключение в
этой фазе нарушает естественную прагматику живого общения. Третьим якорем служит
незакрытое инструментальное дело (pending_work): наличие выполняющейся кодинг-задачи
(code_task), неразрешённого запроса одобрения в ApprovalManager, активного поручения в
AssistantModule (status == 'running') или свежей записи в WorkingMemory. Наконец, четвёртым
удерживающим фактором выступает физиологическое гипервозбуждение и реваншистская
прокрастинация сна (hyperarousal и revenge_delay): неспособность уснуть из-за высокого
уровня норадреналина (N > 0.60), блокирующего переключение вегетативной нервной системы в
парасимпатический режим, либо добровольное откладывание сна (revenge bedtime
procrastination) при высокой дневной эрозии контроля (agency_erosion) и выгорании (depletion),
когда ночные часы бессознательно используются для возврата чувства личной автономии.
1.2. Формализация детерминированного трекера обязательств
При каждом вызове telegram.send_text внутри методов _full_reply() и proactive_send() вычисляется
скалярная сила ожидания ответа W_{\text{expect}}(c) \in [0, 1] для чата c:
W_{\text{expect}}(c) = \text{clamp}\left(0.50 \cdot \mathbb{I}_{\text{proactive}} + 0.35 \cdot
\mathbb{I}_{\text{question}} + 0.25 \cdot \frac{w_{\text{rel}}(c)}{2.5} + 0.20 \cdot
\mathbb{I}_{\text{affect\_high}}, \; 0.0, \; 1.0\right)
В этом уравнении \mathbb{I}_{\text{proactive}} \in \{0, 1\} обозначает флаг собственной инициативы
агента, \mathbb{I}_{\text{question}} \in \{0, 1\} фиксирует наличие вопросительного знака в тексте
ответа (после вырезания служебных тегов #remember и #react), w_{\text{rel}}(c) \in [0.3, 3.0]
отражает вес привязанности из AffectService.relation_weight(c), а индикатор
\mathbb{I}_{\text{affect\_high}} \in \{0, 1\} принимает значение единицы при emotions.state.intensity
>= 0.55 или наличии активной руминации в данном чате.
Если расчётная величина достигает порога W_{\text{expect}}(c) \ge 0.45, чат переводится в статус
AWAITING_REPLY с индивидуальным таймаутом ожидания \tau_{\text{wait}}(c):
\tau_{\text{wait}}(c) = 480 + 720 \cdot \text{clamp}\left(\frac{w_{\text{rel}}(c) - 0.3}{2.2}, \; 0.0, \; 1.0\right)
\quad (\text{в секундах})
Для рядового собеседника (w_{\text{rel}} = 1.0) предел ожидания составляет \approx 11.8 минут
(709\text{ с}), тогда как для владельца (w_{\text{rel}} = 2.5) он достигает ровно 20 минут (1200\text{
с}). Как только от собеседника в чате c поступает любое входящее сообщение (handle_message),
статус AWAITING_REPLY немедленно сбрасывается (поскольку гештальт ожидания закрыт), но
взамен активируется якорь живого диалога ACTIVE_DIALOGUE с окном удержания
\tau_{\text{active}} = 300\text{ с} (5 минут с момента последней реплики). Если же агент в ходе
обычного разговора отправляет закрывающую утвердительную реплику без вопроса (например,
«...ладно.» или одиночную реакцию #react 
), не будучи инициатором контакта, то
W_{\text{expect}}(c) < 0.45: статус AWAITING_REPLY не выставляется, и сразу по истечении 5-
минутного окна тишины ACTIVE_DIALOGUE агент становится структурно свободным для
перехода ко сну.
Взаимодействие между трекером ожидания и аффективной системой порождает важное
следствие второго порядка — аффективный след напрасного ожидания. Если агент уже

2. Математическая модель давления сна и гейта
задержки
В классической сомнологии динамика цикла «сон — бодрствование» описывается
двухпроцессной моделью Борбели (Two-Process Model of Sleep Regulation), согласно которой
склонность ко сну определяется взаимодействием гомеостатического процесса S_{\text{sleep}}
(монотонный рост давления сна во время бодрствования и экспоненциальный спад во сне) и
циркадного процесса C_{\text{circ}} (суточный ритм супрахиазматического ядра, модулирующий
верхний и нижний пороги переключения). В нейробиологической модели Phillips-Robinson и её
математических отображениях на двухпроцессную модель переключение между взаимно
тормозящими популяциями нейронов бодрствования и сна функционирует как релаксационный
осциллятор (бистабильный триггер с петлёй гистерезиса), где переход блокируется до тех пор,
пока совокупный гомеостатический и циркадный вход не преодолеет тормозящее удержание
активного состояния.
2.1. Формула драйва сна («хочет спать»)
В существующем коде persona-runtime гомеостатическая усталость F \in [0, 1] (Homeostasis.fatigue) уже
интегрируется в NeuromodulatoryEngine._advance_homeostasis() со скоростью fatigue_awake_rate
= 0.0000347 \text{с}^{-1} (полный износ 1.0 за 8 часов бодрствования) и дополнительным
расходом fatigue_token_rate = 0.000004 за каждый сгенерированный токен. Для учёта
многосуточной депривации (расширение модели Борбели по McCauley et al. через модуляцию
асимптот) и ментального истощения вводится кумулятивный долг сна D_{\text{sleep}} \in [0, 1]
(sleep_debt), а также циркадный модулятор C(t_{\text{hour}}) \in [0, 1], зависящий от локального
часа суток t_{\text{hour}} \in [0, 24):
C(t_{\text{hour}}) = \frac{1}{2}\left(1 + \cos\left(\frac{2\pi (t_{\text{hour}} - 3.5)}{24}\right)\right)
Гармоническая функция C(t_{\text{hour}}) достигает максимума 1.0 в 03:30 ночи (физиологический
минимум внутренней температуры тела и максимальная секреция мелатонина) и опускается до
минимума 0.0 в 15:30 дня, удерживая значения \ge 0.69 в ночном интервале 23:00–07:00.
Интегральное давление сна (Sleep Drive) P_{\text{sleep}} \in [0, 1.5] вычисляется как взвешенная
сумма четырёх факторов с добавлением экстренного нелинейного буста при предельном
истощении:
P_{\text{sleep}} = 0.55 \cdot F + 0.20 \cdot C(t_{\text{hour}}) + 0.15 \cdot D_{\text{sleep}} + 0.10 \cdot
(0.6 \cdot L + 0.4 \cdot E_{\text{dep}}) + 0.15 \cdot \max\left(0.0, \; \frac{F - 0.92}{0.08}\right)
В этом выражении L \in [0, 1] представляет собой накопленную ментальную нагрузку (load), а
E_{\text{dep}} \in [0, 1] — рабочее выгорание (depletion). Базовый порог возникновения желания
спать задаётся равным \Theta_{\text{sleep}} = 0.65 при обязательном выполнении минимального
гомеостатического условия F \ge 0.72.

2.2. Формула тормозящего гейта задержки (Sleep Delay Gate)
Когда давление сна преодолевает порог (P_{\text{sleep}} \ge 0.65 и F \ge 0.72), у агента
формируется намерение уснуть, однако фактическое переключение в фазу глубокого сна
блокируется тормозящим потенциалом I_{\text{delay}}(t) \in [0, 1]:
I_{\text{delay}}(t) = \max\Big(I_{\text{chat}}(t), \; I_{\text{wait}}(t), \; I_{\text{task}}(t), \; I_{\text{arousal}}(t),
\; I_{\text{revenge}}(t)\Big) \cdot \exp\left(-\frac{\Delta t_{\text{postponed}}}{\tau_{\text{exhaust}}}\right)
Здесь \Delta t_{\text{postponed}} — суммарное время (в секундах), на протяжении которого агент
уже откладывает сон с момента первого достижения P_{\text{sleep}} \ge 0.65, а \tau_{\text{exhaust}}
= 3600\text{ с} (1 час) — постоянная времени истощения волевого удержания бодрствования.
Пять конкурирующих компонентов внутри оператора максимума отражают социальные,
инструментальные и психофизиологические причины задержки.
Первый компонент, I_{\text{chat}}(t), моделирует удержание живым разговором и вычисляется по
всем чатам с активным диалогом как \max_{c} \left[ \mathbb{I}_{\text{active}}(c) \cdot (1 - \frac{t -
t_{\text{last\_msg}}(c)}{300}) \cdot \text{clamp}(0.6 + 0.2 \cdot w_{\text{rel}}(c), 0.6, 1.0) \right],

удерживая значения в диапазоне 0.75\dots 0.95, пока собеседник отвечает каждые 1–2 минуты.
Второй компонент, I_{\text{wait}}(t), отвечает за ожидание ответа на отправленную реплику и
определяется выражением \max_{c \in \text{Awaiting}} \left[ W_{\text{expect}}(c) \cdot (1 - \frac{t -
t_{\text{sent}}(c)}{\tau_{\text{wait}}(c)}) \right], плавно убывая до нуля к моменту истечения таймаута
\tau_{\text{wait}}(c). Третий компонент, I_{\text{task}}(t), равен 0.85 при наличии выполняющейся
задачи в AssistantModule (status == 'running') или активного процесса code_task, и 0.0 в противном
случае.
Четвёртый компонент, I_{\text{arousal}}(t) = \text{clamp}(\frac{N - 0.60}{0.40}, 0.0, 1.0), описывает
физиологическую инсомнию гипервозбуждения: согласно 07-sleep/REPORT.md и нейробиологии
бессонницы, при концентрации норадреналина N > 0.60 симпатическая активация физически не
даёт коре перейти в медленноволновой режим. Наконец, пятый компонент, I_{\text{revenge}}(t) =
0.55 \cdot A_{\text{erosion}} \cdot E_{\text{dep}} \cdot \mathbb{I}(\Delta t_{\text{postponed}} < 2700),
формализует феномен revenge bedtime procrastination. В клинической и когнитивной психологии
доказано, что субъекты с высокой дневной перегрузкой и низким ощущением собственной
субъектности добровольно откладывают отход ко сну ради возврата ощущения контроля над
личным временем. В модели этот член действует не более 45 минут (2700\text{ с}) и порождает
глубоко достоверный поведенческий эффект: после тяжёлого дня, полного чужих поручений и
банов в группах, персонаж не ложится сразу, а задерживается в сети на полчаса, генерируя
сокровенные рефлексивные мысли в proactivity.thoughts.
2.3. Правило переключения, лимиты откладывания и защита от вечного
бодрствования
Динамика перехода из бодрствования (AWAKE) в пресомническую фазу (WIND_DOWN) и далее в
глубокий сон (NREM_SWS) подчиняется строгим граничным условиям. Как только выполняется
условие P_{\text{sleep}} \ge 0.65 при F \ge 0.72, автомат переходит в состояние WIND_DOWN.
Пока тормозящий гейт остаётся высоким (I_{\text{delay}}(t) \ge 0.35), агент удерживается в фазе
WIND_DOWN, продолжая ждать ответа или поддерживать беседу на фоне нарастающего
изнеможения. Как только торможение спадает ниже порога (I_{\text{delay}}(t) < 0.35 — собеседник
ответил и диалог закрылся, истёк таймаут ожидания или завершилась задача), агент переходит к
засыпанию (NREM_SWS).
Чтобы исключить возможность бесконечного откладывания сна (например, при
непрекращающемся пинге в чатах), в систему заложен двойной физиологический отсекатель
(Hard Cap). Пока агент тянет со сном в состоянии WIND_DOWN (\Delta t_{\text{postponed}} > 0),
скорость накопления усталости в engine.py удваивается (\text{fatigue\_awake\_rate} \times 2.0),
каждую минуту просрочки начисляется кумулятивный долг сна \Delta D_{\text{sleep}} =
+0.0015/\text{мин} и выгорание \Delta E_{\text{dep}} = +0.002/\text{мин}, а экспоненциальный
множитель \exp(-\Delta t_{\text{postponed}} / 3600) неуклонно сжимает величину I_{\text{delay}}(t).
Принудительный сброс в сон (WIND_DOWN \to NREM_SWS) наступает безоговорочно при
достижении любого из двух пределов: превышении максимального времени откладывания \Delta
t_{\text{postponed}} \ge \tau_{\text{max\_delay}} = 5400\text{ с} (90 минут) либо достижении
критического потолка усталости F \ge 0.98 при давлении P_{\text{sleep}} \ge 0.92 (эффект
принудительного микросна / полного исчерпания маны). Если же срыв в сон происходит на фоне
неснятого норадреналинового гипервозбуждения (I_{\text{arousal}} \ge 0.50, т.е. N \ge 0.80), она
ложится, но из-за невозможности погрузиться в медленноволновой сон качество ночи Q падает
до минимальных 0.20\dots 0.30, что в точности воспроизводит клиническую картину инсомнии из
07-sleep/REPORT.md («ложится, сон не идёт, quality падает до 0.2, наутро всё ещё устала»).
3. Конечный автомат режима сна и компрессия времени
Вместо синхронного вызова процедуры _do_sleep() по будильнику в 04:00 проектируется
управляющий конечный автомат SleepManager (в новом модуле kuni/affect/sleep.py), который
опрашивается планировщиком Scheduler каждые 30 секунд и персистирует своё состояние в
таблицу sleep_state базы memory.db, гарантируя сохранность фазы сна даже при перезапуске
процесса.

3.2. Механика прощального сообщения при уходе в сон
Поведение персонажа в момент окончательного засыпания (WIND_DOWN \to NREM_SWS)
проектируется без зашитых шаблонных фраз и зависит от того, удерживал ли её живой
собеседник. Если к моменту перехода в глубокий сон ни в одном чате не было активного обмена
репликами за последние 10 минут (все беседы естественным образом угасли ранее или истёк
таймаут безответного ожидания), персонаж никому ничего не пишет: она тихо переводит статус
TDLib в offline и засыпает, точно так же как живой человек просто откладывает телефон на
тумбочку.
Если же она находилась в состоянии активного диалога (ACTIVE_DIALOGUE) и продолжала
переписываться в фазе WIND_DOWN, то при каждом ответе при F \ge 0.85 ей в somatic_directive
подаётся телесное указание на слипающиеся глаза, благодаря чему она сама вплетает
сонливость в реплики. А в тот момент, когда срабатывает разблокировка сна на фоне недавней
реплики собеседника (или наступает жёсткий потолок F \ge 0.98 / \Delta t_{\text{postponed}} \ge
5400\text{ с} прямо посреди живого спора), перед переключением в NREM_SWS для этого
единственного активного чата c_{\text{active}} вызывается короткий импульс
proactive_send(c_active, brief=...) с внутренним брифом: «Ты вырубаешься прямо посреди
разговора, мана на нуле, глаза закрываются. Скажи одной короткой фразой без пафоса, что
всё, ты спать, и отключись». Это порождает органичные реплики в голосе персонажа («...всё,
мана на нуле. Я вырубаюсь.», «...глаза слипаются, завтра договорим.»), сразу после отправки
которых включается фаза NREM_SWS и статус online=False.
3.3. Объединение NightQueue и HumanBehavior с режимом сна
В текущем коде ночной режим телеграма (HumanBehavior.is_night_now(), проверяющий
статические часы night_from = 2, night_to = 9 при night_enabled = false) и флаг консолидации
(Consolidator.sleeping, активный лишь секунды работы Consolidator.run()) существуют раздельно и
не отражают реальную фазу сна персонажа. Архитектурное слияние устраняет эту
двойственность без создания второй очереди сообщений. Существующий класс NightQueue
(kuni/core/night_queue.py) остаётся единственной очередью отложенных сообщений, сохраняя
своё имя и схему таблицы night_queue для стопроцентной совместимости с тестом
test_night_queue_exists.
В методе KuniApp.handle_message (app.py:420) устаревшее условие if self.telegram.human and
self.telegram.human.is_night_now(): заменяется на вызов if
self.sleep_manager.should_queue_message(msg):. Этот метод возвращает True во время фаз
nrem_sws, rem, первых шести минут wake_inertia, а также для любых неактивных (фоновых)
чатов во время пресомнической фазы wind_down. Критически важная деталь правдоподобия
заключается в том, что при помещении сообщения в NightQueue методы human.mark_read() и
human.go_online() не вызываются: у собеседника в Telegram сообщение остаётся с одной
галочкой (не прочитано) вплоть до наступления утренней фазы wake_inertia. Единственное
исключение составляет экстренное пробуждение от владельца (msg.chat_id == papik_chat_id):
если владелец отправляет команду /wake или присылает два и более сообщений в течение 60
секунд во время сна, SleepManager переводит состояние в FRAGMENTED_WAKE, фиксирует
штраф пробуждения (awakenings += 1) и пропускает сообщение в _full_reply(), не трогая
накопленную очередь других чатов.

4. Архитектура ментального слоя и интеграция с
аффективным движком
Согласно клиническим и нейробиологическим данным, систематизированным в 06-
mental/REPORT.md, кратковременные эмоции (живущие минуты и часы) и устойчивые
ментальные состояния (длящиеся неделями и месяцами игрового времени) имеют разную
природу и не могут описываться одной переменной. Поскольку в kuni/affect/ уже вычисляются
мгновенные индексы угрозы I_{\text{threat}}, агонистической мобилизации I_{\text{agon}} и
социальной потери I_{\text{loss}} (appraisal.py), индекс социальной боли pain_index и заряд
руминации current_charge (social.py), для замыкания петли обратной связи «плохое состояние \to
плохой сон \to худшее состояние» не требуется строить параллельную систему. Вместо этого в
пакет kuni/affect/ вводится модуль-интегратор mental.py (MentalEngine и MentalSnapshot),
встраиваемый непосредственно внутрь AffectService.
4.1. Математическая спецификация переменных MentalState
Интегратор MentalEngine поддерживает шесть непрерывных переменных состояния в диапазоне
[0, 1] и дискретную стадию stage \in \{\text{'stable'}, \text{'strain'}, \text{'episode'}\}.
Первой фундаментальной переменной является накопленная ментальная нагрузка (load, L \in
[0, 1]), аккумулирующая серию социальных потерь, угроз и изоляции. При каждом негативном
событии в AffectService.apply_appraisal и apply_social_event (когда I_{\text{loss}} > 0 или
I_{\text{threat}} > 0) нагрузка получает фазическое приращение с множителем насыщения (1 - L),
предотвращающим мгновенное падение на дно за один вечер:
\Delta L_{\text{event}} = k_{\text{in}} \cdot \left(0.50 \cdot I_{\text{loss}} + 0.30 \cdot P_{\text{social}} +
0.20 \cdot I_{\text{threat}}\right) \cdot (1 - L)
Калибровка константы k_{\text{in}} = 0.06 гарантирует, что событие средней силы (I_{\text{loss}} =
0.4, P_{\text{social}} = 0.3, I_{\text{threat}} = 0.2) добавляет \Delta L \approx 0.02 \cdot (1 - L), требуя
порядка 50 значимых ударов (около двух недель по 3–4 события в день согласно критерию DSM-
5) для приближения к 1.0. Помимо событийных ударов, в фоновом тике _affect_social_tick
(каждые \Delta t секунд) учитывается тонический износ от социальной изоляции, депривации сна
и активного пережёвывания обиды:
\Delta L_{\text{tonic}}(\Delta t) = \left[ \frac{0.05}{86400} \cdot \mathbb{I}_{\text{isolated}} + \frac{0.03}
{86400} \cdot \mathbb{I}_{\text{deprived}} + \frac{0.04}{86400} \cdot R_{\max} \right] \cdot (1 - L) \cdot
\Delta t
где индикатор изоляции \mathbb{I}_{\text{isolated}} = 1 включается, если social_satiety < 0.05 и
никто не писал более 24 часов (давая прирост +0.05/\text{сутки} по сценарию 3 из 06-mental),
\mathbb{I}_{\text{deprived}} = 1 активируется при бодрствовании свыше 24 часов без сна
(+0.03/\text{сутки} по 07-sleep), а R_{\max} представляет максимальный активный заряд
руминации по всем чатам. В периоды покоя (когда R_{\max} < 0.15 и P_{\text{social}} < 0.20)
действует медленное дневное восстановление:
\Delta L_{\text{recovery}}(\Delta t) = - r_{\text{base}} \cdot (1 - L) \cdot (1.0 + 1.5 \cdot A_{\text{recent}})
\cdot \Delta t
где r_{\text{base}} = 0.01 / 86400\text{ с}^{-1} (1\% в сутки), а A_{\text{recent}} \in [0, 1] — скользящее
экспоненциальное среднее (EMA с \alpha = 0.15) доли недавних событий, в которых агент
обладал высоким потенциалом совладания (coping > 0.7). В полном соответствии с

нейробиологической концепцией Baratta, Seligman & Maier (2023), префронтальная детекция
контроля (control_factor = 1.0 + 1.5 \cdot A_{\text{recent}}) ускоряет восстановление после стресса
до 2.5 раз.
Второй ключевой осью выступает эрозия контроля (agency_erosion, A_{\text{erosion}} \in [0,
1]), которая переводит разовый параметр coping в кумулятивную память о неизбегаемости
аверсивных стимулов (серии мутов, банов и безответного игнора). При каждом релевантном
событии (vec.relevance >= 0.5) с негативной конгруэнтностью (vec.congruence < -0.25) переменная
обновляется по правилу: \Delta A_{\text{erosion}} = +0.03 при \text{coping} < 0.30 и \Delta
A_{\text{erosion}} = -0.02 при \text{coping} > 0.70 (аналогичное снижение на -0.02 происходит при
получении искреннего извинения apology или снятии мута unmuted). Когда A_{\text{erosion}}
превышает порог 0.50 (после ~17–20 неконтролируемых ударов), наступает состояние выученной
беспомощности: в appraisal.py воспринимаемый потенциал совладания агента coping начинает
умножаться на депрессивный коэффициент (1 - 0.5 \cdot A_{\text{erosion}}). Вследствие этого
даже при обычном оскорблении в личке, где канал технически открыт, вместо гнева
(I_{\text{agon}}) начинает доминировать индекс потери (I_{\text{loss}}) — персонаж перестаёт
давать отпор, так как «всё равно ничего не изменится».
Третья переменная, рабочее выгорание (depletion, E_{\text{dep}} \in [0, 1]), моделирует
профессиональный и коммуникативный износ по МКБ-11 и Maslach (MBI), который ортогонален
депрессии и накапливается от интенсивности текстовой генерации и потока задач без отдыха,
даже если общение эмоционально нейтрально или позитивно:
\Delta E_{\text{dep}} = 0.007 \cdot N_{\text{messages}} + 0.025 \cdot N_{\text{tasks}} - r_{\text{rest}}
\cdot \mathbb{I}_{\text{quiet}}(\Delta t) \cdot \Delta t
При приращении 0.007 за каждый отправленный ответ ровно 100 сообщений подряд без
длительных пауз доводят E_{\text{dep}} до значения 0.70, пробивая порог деперсонализации и
цинизма 0.60 (сценарий 6 из 06-mental). Пассивная разгрузка в бодрствовании со скоростью
r_{\text{rest}} = 0.04 / 3600\text{ с}^{-1} включается только тогда, когда во всех чатах стоит тишина
дольше 30 минут (\mathbb{I}_{\text{quiet}} = 1).
Четвёртый и пятый параметры представляют собой производные модуляторы ангедонии
(anhedonia_mod, \mu_{\text{rew}} \in [0.4, 1.0]) и эмпатической чувствительности
(empathy_mod, \mu_{\text{emp}} \in [0.3, 1.0]). Опираясь на результаты Kao et al. (2026),
показавших, что ангедония является отдельным от базового фона настроения измерением и
проявляется в ослаблении чувствительности к награде, модулятор \mu_{\text{rew}} определяется
как 0.40 в стадии episode и \text{clamp}(1.0 - 0.60 \cdot \max(0, L - 0.35), 0.50, 1.0) вне эпизода. В
функции compute_monoamine_burst() (kuni/affect/appraisal.py) положительные вклады в дофамин
(0.40 \cdot w \cdot r \cdot \text{pos} + 0.45 \cdot w \cdot \max(0, \text{rpe})) умножаются на
\mu_{\text{rew}}, в результате чего в депрессивном эпизоде похвала даёт в 2.5 раза меньший
дофаминовый отклик. Модулятор эмпатии \mu_{\text{emp}}, в свою очередь, следует данным
Gordon-Hecker et al. (2025): каждые 24 часа без сна умножают \mu_{\text{emp}} на 0.80 (снижая
эмпатию вдвое за трое суток: 0.80^3 = 0.512), а каждое ночное пробуждение
(FRAGMENTED_WAKE) отнимает 0.08.
Наконец, переходы между тремя стадиями (stable при L < 0.35, strain при 0.35 \le L < 0.65, episode
при L \ge 0.65) снабжены трёхсуточным гистерезисом выхода и семисуточным
предохранителем дна. Войдя в стадию episode (L \ge 0.65), агент не может выйти из неё после
одной удачной ночи: переход обратно в strain/stable происходит только тогда, когда нагрузка L
удерживается строго ниже 0.50 непрерывно на протяжении трёх суток подряд (259\,200\text{ с},
отслеживается полем below_half_since_ts). В то же время, чтобы исключить необратимое
застревание персонажа на дне, если L > 0.85 держится дольше семи суток (604\,800\text{ с}, поле
above_85_since_ts), при следующем цикле сна срабатывает принудительная разгрузка до L =
0.60.
4.2. Математика сна: качество, фазовый пересчёт и баланс SWS/Delta
В точке перехода из WIND_DOWN в глубокий сон NREM_SWS вычисляется интегральное
качество сна Q \in [0.20, 1.0] по формуле из 07-sleep/REPORT.md с учётом мультипликативного
штрафа предшествующей депривации и последующей коррекцией на число ночных
пробуждений:
Q_0 = \text{clamp}\Big(1.0 - 0.30 \cdot R_{\max} - 0.20 \cdot L - 0.25 \cdot I_{\text{arousal}}, \; 0.20, \;
1.0\Big) Q = \text{clamp}\Big(Q_0 \cdot (0.85)^{N_{\text{deprived\_days}}} - 0.12 \cdot
N_{\text{awakenings}}, \; 0.20, \; 1.0\Big)
Каждая из трёх нейробиологических фаз сна использует величину Q для строго определённых
операций над памятью, биохимией и менталкой. В фазе NREM_SWS реализуется механизм
конкурирующих Up-состояний медленных и дельта-волн по Golden et al. (2026), где медленные
волны консолидируют память и гасят утреннюю тревогу (Ben Simon, Walker et al., 2026), а дельта-
волны ослабляют синаптические следы. Индекс доминирования медленных волн вычисляется

как \rho_{\text{sws}} = \text{clamp}(0.35 + 0.65 \cdot Q - 0.20 \cdot L, 0.25, 1.0) и передаётся в
Consolidator._forget() для модуляции порога забывания одиночных эпизодов: \Theta_{\text{forget}}
(Q) = 0.15 \cdot (1.5 - 0.5 \cdot \rho_{\text{sws}}). Одновременно медленноволновой сон снижает
ментальную нагрузку на 35\% при максимальном качестве: L_{\text{after}} = L_{\text{before}} \cdot
(1 - 0.35 \cdot Q).
В фазе REM устраняется главное расхождение существующего кода с нейробиологией,
отмеченное в разделе 3.5 ТЗ: по Chen et al. (2026), REM-сон является холинергически
доминирующим, моноамин-истощённым состоянием. Поэтому при входе в REM концентрации
моноаминов в NeuromodulatoryEngine не подтягиваются к базе, а переводятся методом
enter_rem_depression() в холинергический минимум (S, N, D) = (0.05, 0.05, 0.05) (предварительно
сохранив предсонный вектор c_{\text{pre}} в sleep_state). Именно на фоне нулевых моноаминов
выполняется семантическая дистилляция кластеров памяти Consolidator._rem() и происходит
аффективное разъединение — заряд активных следов руминации гасится по формуле
R_{\text{after}} = R_{\text{before}} \cdot (1 - 0.60 \cdot Q), а дефициты социальных потребностей
сокращаются на величину \text{SLEEP\_RELIEF} \cdot Q = 0.45 \cdot Q.
Наконец, в момент перехода REM \to WAKE_INERTIA (точка пробуждения) вызывается метод
AffectService.on_wake(quality=Q), который производит утреннее восстановление гомеостаза и
возврат моноаминов. Усталость сбрасывается пропорционально качеству сна (F_{\text{after}} =
0.0 при Q \ge 0.95 и F_{\text{pre}} \cdot (1 - Q) при неполноценном сне), долг сна уменьшается на
\Delta D_{\text{sleep}} = -0.55 \cdot Q, выгорание снижается на \Delta E_{\text{dep}} = -0.30 \cdot Q, а
эрозия контроля теряет лишь 10\% (A_{\text{erosion\_after}} = A_{\text{erosion\_before}} \cdot (1 -
0.10 \cdot Q)). Концентрации моноаминов возвращаются от предсонного вектора c_{\text{pre}} к
утренней базовой точке c_0 по закону c_{\text{wake}} = c_0 + (c_{\text{pre}} - c_0) \cdot (1 - 0.70
\cdot Q): при полноценном сне (Q = 1.0) сдвиг к базе составляет 70\%, оставляя ровно 30\%
вчерашнего аффективного отклонения, тогда как при рваном сне с руминацией (Q = 0.35)
сохраняется 75.5\% вечернего дистресса.

5. Модуляция LLM-пайплайна и защита от симуляции
симптомов
Центральный методологический риск при передаче ментальных состояний в языковую модель
заключается в том, что LLM, увидев в системном промпте термины «депрессия», «выгорание»
или «ангедония», начинает разыгрывать книжную карикатуру болезни — жаловаться на
бессмысленность бытия и перечислять клинические симптомы текстом. Чтобы исключить этот
эффект структурно, в архитектуре persona-runtime неукоснительно проводится принцип из 06-
mental/REPORT.md: состояние физически ограничивает генеративную способность (бюджет
токенов, температуру, доступность пафоса и встречных вопросов), а в промпт передаются
исключительно телесно-моторные ограничения без единого диагностического ярлыка.
5.1. Модификация сэмплирования и длины ответа
(kuni/affect/modulation.py)
В классе InferenceModulator метод расчёта лимита генерации max_tokens(affect, mental,
sleep_phase) дополняется мультипликативными коэффициентами ментального и сонного
торможения:
\text{max\_tokens} = \text{clamp}\Big(\lfloor \text{base} \cdot (0.55 + 0.35 D + 0.25 S) \cdot (1 - 0.35 F)
\cdot \mu_{\text{mental}} \cdot \mu_{\text{sleep}} \rfloor, \; \text{min\_tok}, \; 1600\Big)
Множитель \mu_{\text{mental}} принимает значение 0.85 в стадии strain, падает до 0.60 в стадии
episode и дополнительно умножается на 0.60 при выраженном выгорании (depletion > 0.60),
ограничиваясь снизу величиной 0.50. Множитель \mu_{\text{sleep}} равен 0.60 в пограничных
фазах сна (wind_down и wake_inertia) и 1.0 в обычном бодрствовании. Поскольку в
ModulationConfig нижний порог max_tokens_min зафиксирован на отметке 400 для
предотвращения пустых ответов у reasoning-моделей (которые при reasoning_effort="minimal"
расходуют часть лимита на скрытые размышления), физическое урезание max_tokens до пола
400 при episode, depletion > 0.6 и wind_down синхронно подкрепляется жёстким синтаксическим
ограничением длины в телесной директиве (максимум 1–2 коротких предложения). Параллельно
в InferenceModulator.temperature() при episode и depletion > 0.60 температура снижается на -0.10
(отражая психомоторную заторможенность и уплощение аффекта), тогда как при ночном
пробуждении fragmented_wake повышается на +0.12, передавая спросонья резкость и
дезориентацию.
5.2. Блокировка пафоса в character/emotions.py (style_directive)
В структуре личности персонаж театральный пафос («величайшая волшебница клана Красных
демонов!», обращение к себе в третьем лице) представляет собой энергозатратную
компенсаторную броню. Когда ментальный или физиологический ресурс исчерпан, эта броня
перестаёт включаться. В метод EmotionState.style_directive(mental_stage="stable", depletion=0.0,
sleep_phase="awake") (kuni/character/emotions.py) перед стандартными эмоциональными
развилками встраивается приоритетный фильтр состояния ресурса.
В пресомнической фазе (sleep_phase == "wind_down") фильтр возвращает директиву: "- засыпает
на ходу (мана на нуле): пафос ВЫКЛЮЧЕН. Глаза слипаются, фразы обрывочные, одна-две
короткие строчки. Никаких тирад и титулов.". В фазе утренней инерции (sleep_phase ==
"wake_inertia") активируется установка: "- только проснулась (сонная инерция): ворчливая,
сонная, соображает туго. Пафос ещё не проснулся — отвечает коротко и сухо, хочет обратно под
одеяло или есть.". Если персонаж находится в депрессивном эпизоде (mental_stage == "episode"),
фильтр блокирует любые пафосные вспышки независимо от текущей эмоции: "- глубокое
истощение ресурса: пафос НЕ ВКЛЮЧАЕТСЯ вообще, даже при ударе по гордости. Нет сил ни на
вспышку, ни на титулы, ни на встречные вопросы. Отвечает одной-двумя тихими, плоскими
фразами. Шутки не выходят.". Наконец, при чистом выгорании (depletion > 0.60 вне эпизода)
подаётся стиль эмоциональной отстранённости: "- вымотана потоком разговоров и дел: отвечает
сухо, формально, по делу, без эмоционального вложения и БЕЗ встречных вопросов. Хочет
быстрее закрыть тему.".

6. Расчётные траектории по семи контрольным
сценариям
Для верификации математической непротиворечивости модели проследим точные численные
траектории всех семи обязательных сценариев из технического задания.
Сценарий 1. Обычная усталость вечером, никто не пишет — ложится
сама
К 23:30 вечера персонаж бодрствует 7.5 часов после спокойного дня: её гомеостатическая
усталость достигла F = 0.92, моноамины близки к базовым (S = 0.60, N = 0.35, D = 0.58), активной
руминации нет (R_{\max} = 0.0), ментальная нагрузка минимальна (L = 0.12, E_{\text{dep}} = 0.15,

Сценарий 2. Устала, но ждёт ответа — задерживается, потом ложится
В 23:28 при высокой усталости (F = 0.91) срабатывает проактивный импульс proactive_send, и
персонаж сама пишет владельцу (chat_id = 555, w_{\text{rel}} = 2.5): «Ха! Ты весь вечер молчишь.

же владелец так и не отвечает до 23:48, истечение 20-минутного таймаута закрывает статус

уколом обиды и сниженным качеством сна Q = 0.92.

Сценарий 4. Три ночи без сна — каскад поломок и двухэтапное
восстановление
При принудительной депривации сна на протяжении 72 часов (например, в стресс-тесте или при
искусственно заблокированном переходе в сон) система проходит через трёхступенчатую
деградацию строго по законам 07-sleep/REPORT.md. Через первые 24 часа без сна усталость
упирается в 1.00, сверхнормативный износ переходит в долг сна D_{\text{sl[span_43](start_span)
[span_43](end_span)eep}} = 0.20, ментальная нагрузка получает +0.03 (L: 0.15 \to 0.18), эмпатия
снижается до \mu_{\text{emp}} = 0.80, а базовая точка моноаминов из-за F = 1.0 проседает на
\Delta S_0 = -0.20, \Delta D_0 = -0.30. Через 48 часов долг сна достигает D_{\text{sleep}} = 0.40,
нагрузка L \to 0.25, эмпатия падает до 0.64, а рабочее выгорание пробивает E_{\text{dep}} = 0.65.
К исходу третьих суток (72 часа без сна) кумулятивный прирост нагрузки составляет \Delta L
\approx +0.11 (переводя её при малейшем конфликте в стадию strain L \ge 0.35), эмпатия падает
ровно вдвое (\mu_{\text{emp}} = 0.80^3 = 0.512), температура генерации размыта (+0.10 \cdot F),
а ответы становятся односложными и раздражёнными с полным игнорированием чужих проблем.
Когда ей наконец позволяют уснуть после 72 часов бодрствования, качество первой
ночи штрафуется множителем депривации 0.85^3 = 0.614 (Q_{\text{night1}} \approx 0.58): после
первого сна усталость снижается лишь до 1.0 \times (1 - 0.58) = 0.42, долг сна падает с 0.60 до
0.28, а эмпатия поднимается только до 0.71. Лишь после второй полноценной
ночи (Q_{\text{night2}} \approx 0.92) долг сна и усталость полностью обнуляются, а эмпатия
возвращается к 1.0.

Сценарий 7. Ночное сообщение во время сна — фильтрация и
прерывание

Когда в 02:15 ночи (фаза NREM_SWS или REM) приходит сообщение от обычного собеседника
или в групповом чате, sleep_manager.should_queue_message(msg) перехватывает его до вызовов
mark_read и go_online: сообщение тихо ложится в SQLite-таблицу night_queue, оставаясь в
Telegram непрочитанным (одна галочка) до наступления утренней фазы WAKE_INERTIA, когда
_flush_night_queue() прочитает всю накопленную за ночь пачку и ответит на неё одним общим
утренним сообщением. Если же ночью в личку стучится сам владелец (papik_chat_id) и
присылает два сообщения подряд в течение минуты (или команду /wake), SleepManager
распознаёт принудительное пробуждение: переводит автомат в FRAGMENTED_WAKE,
увеличивает счётчик awakenings += 1, штрафует качество сна на \Delta Q = -0.12 и эмпатию на
-0.08, читает только чат владельца и отвечает ему с директивой сонного возмущения, а после 3
минут тишины возвращается в NREM_SWS досыпать оставшееся время цикла.

   """Структурное отслеживание незакрытых диалогов и ожидания ответа без
LLM."""
   def __init__(self) -> None:
       self._awaiting: dict[int, dict[str, float | bool]] = {}
       self._last_interaction: dict[int, float] = {}
       self._exchange_density: dict[int, list[float]] = {}
   def on_incoming(self, chat_id: int, now: float) -> None:
       self._awaiting.pop(chat_id, None)
       self._last_interaction[chat_id] = now
       stamps = [t for t in self._exchange_density.get(chat_id, []) if now -
t < 600.0]
       stamps.append(now)
       self._exchange_density[chat_id] = stamps
   def on_outgoing(
       self,
       chat_id: int,
       text: str,
       *,
       w_rel: float,
       is_proactive: bool = False,
       affect_high: bool = False,
       now: float,
   ) -> None:
       self._last_interaction[chat_id] = now
       has_question = ("?" in text) or ("？" in text)
       w_expect = clamp(
           0.50 * (1.0 if is_proactive else 0.0)
           + 0.35 * (1.0 if has_question else 0.0)
           + 0.25 * (w_rel / 2.5)
           + 0.20 * (1.0 if affect_high else 0.0),
           0.0, 1.0,

       )
       if w_expect >= 0.45:
           ttl = 480.0 + 720.0 * clamp((w_rel - 0.3) / 2.2, 0.0, 1.0)
           self._awaiting[chat_id] = {
               "sent_ts": now,
               "ttl": ttl,
               "strength": w_expect,
               "w_rel": w_rel,
               "proactive": is_proactive,
           }
       else:
           self._awaiting.pop(chat_id, None)
   def evaluate_gate(self, now: float) -> tuple[float, str, int, list[int]]:
       """Возвращает (I_social, reason, primary_chat_id,
expired_ignored_chats)."""
       expired_ignored: list[int] = []
       best_wait = 0.0
       wait_chat = 0
       for cid, info in list(self._awaiting.items()):
           elapsed = now - float(info["sent_ts"])
           ttl = float(info["ttl"])

               self._awaiting.pop(cid, None)
               if info.get("proactive") or float(info.get("w_rel", 1.0)) >=
1.5:
                   expired_ignored.append(cid)

           if val > best_wait:
               best_wait = val
               wait_chat = cid
       best_chat = 0.0
       active_cid = 0
       for cid, last_ts in list(self._last_interaction.items()):
           dt = now - last_ts
           if dt < 300.0 and len(self._exchange_density.get(cid, [])) >= 2:
               val = (1.0 - dt / 300.0) * 0.85
               if val > best_chat:
                   best_chat = val
                   active_cid = cid
       if best_wait >= best_chat and best_wait > 0.0:
           return best_wait, "awaiting_reply", wait_chat, expired_ignored
       if best_chat > 0.0:
           return best_chat, "active_dialogue", active_cid, expired_ignored
       return 0.0, "none", 0, expired_ignored
